# 关闭、卸载与恢复

先用 `node scripts/install.mjs --help` 核对当前命令。不要删除用户原配置、字体或数据库来排错。

## 单独关闭Gemini 4默认1M

备份安装目录的config.json，将 `gemini1m` 设为false，保留其他字段。对本安装器的服务执行 `launchctl kickstart -k gui/$(id -u)/com.chuanban.antigravity-theme-patch`，然后**完全退出并重开Antigravity**。仍在运行的窗口可能保留旧请求包装或重载脚本，改文件不等于即时恢复。

新消息中不再加入1M参数。已经按较大预算运行的历史记录不会被改写，当前会话的启动配置也可能保留独立覆盖；以新普通会话验证恢复默认，不能仅检查旧指标文本。

## 停止常驻

```sh
node scripts/install.mjs stop
```

这只停止后台进程。当前窗口的CSS/事件监听可能仍存在；完全退出重开后清除。已安装字体仍保留。

## 完整卸载

```sh
node scripts/install.mjs uninstall
```

安装器只处理有自身manifest的目录及其服务；移到可恢复的备份，不清空数据库或字体目录。未知旧安装需人工核对归属，不绕过保护强删。

退出并重开Antigravity，再在官方设置中恢复安装前的System/Light/Dark模式及原生颜色。网页localStorage备份不等于原生外观设置，不能承诺一条命令100%还原所有系统设置。

## 恢复上次安装

升级前完整备份保存在安装器输出的位置。先停止当前服务，保留当前目录作为回退记录，再恢复已核对的备份目录与对应LaunchAgent；重启补丁服务及客户端。若Node版本更新导致固定可执行路径失效，重新生成LaunchAgent，不能只复制旧路径。

## 安装失败

- Node/SQLite不兼容：停止安装，使用符合版本要求的Node，不安装不明npm依赖。
- CDP端口失效：核对客户端是否运行及当前端口，不复用旧端口。
- 字体未生效：检查内部名称，正常重启客户端；不要重复覆盖同PostScript名称的字体。
- 白屏或界面故障：先停止补丁并重启客户端，再分模块排查，保留备份和错误证据。
- 升级遇到已有目录：使用 `--upgrade` 并检查完整备份，不删除目录重试。
